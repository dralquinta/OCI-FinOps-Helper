# Standalone binary

Build on Linux x86_64 with `bash build.sh`. The executable is `dist/oci-finops-helper`; Python and OCI CLI are embedded. Build dependencies require package-index access. Binaries are native to the build OS/architecture and require its compatible system C library; the Linux CI builder uses Ubuntu 22.04. Native local builds use the local platform. The binary does not install a Jupyter server.

Run `./dist/oci-finops-helper <tenancy_ocid> <home_region> <from_date> <to_date>` with the same stage flags as collector.sh. Existing OCI CLI authentication configuration and environment variables remain applicable. Collection runs in an isolated temporary directory. On success the binary emits `oci-finops-collection-<timestamp>-<id>.tar.gz` in the invocation directory. Set `--archive-dir <directory>` to choose another destination. Archive members use relative `output/` paths. Metadata cache compatibility uses `~/.cache/oci-finops-helper/instance_metadata_cache.json`; set `--cache-dir <directory>` to override. Only this known file is seeded into each isolated collection and atomically persisted after successful collection/archive delivery. Failed collection leaves existing cache unchanged; symlink paths are rejected. The metadata collector validates cache tenancy, region and TTL when that collector support is installed. Inspect with `tar -tzf <archive>` and extract into a chosen empty directory.

Collection errors return a nonzero status and produce no success archive; temporary partial outputs are removed. A requested stage that reports a nonfatal warning retains the source collector status semantics. No new cloud operations are introduced.

Run `./dist/oci-finops-helper --extract-suite <empty-directory>` to extract packaged production Python source, notebooks, documentation, requirements, shell wrapper and license. Production source preserves its relative src/ layout so notebooks can import shared helpers, including helpers added by future merged changes. Source Python is copied verbatim to preserve parser/type-prefix semantics. These are allowlisted source assets: notebook outputs, execution counts and metadata are removed, and literal OCI identifiers are replaced by placeholders at build time. Source notebooks remain unchanged. Extracted notebooks require their notebook dependencies if run separately; install the extracted requirements.txt in a Python environment. The extracted source CLI/shell wrapper additionally needs an externally installed OCI CLI, while the standalone executable embeds its OCI CLI. Run extracted notebooks from the suite root so the src namespace is importable. Credentials, customer_files, runtime output and TDD records are excluded.

`python3 scripts/smoke_binary.py dist/oci-finops-helper` verifies the actual binary with an empty PATH: help, bundled OCI CLI version, an offline collection with all stages skipped, emitted tar.gz contents, invalid-argument failure and suite extraction. It never contacts OCI. An all-skipped collection archive contains its success manifest and any seeded metadata cache.
